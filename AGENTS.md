# Project guidance

- This project uses a `src` layout: install it with `.\.venv\Scripts\python.exe -m pip install -e .` before running the CLI or tests. See `README.md` for virtual-environment setup.
- Both `python -m elastic_netmap_gen` and the installed `elastic-netmap-gen` command call `src/elastic_netmap_gen/cli.py:main`.
- CSV parsing and host merging live in `src/elastic_netmap_gen/inventory.py`; diagram export lives in `src/elastic_netmap_gen/drawio.py`. Preserve multi-IP hosts as single nodes. Draw only inventory devices and explicitly configured connections; retain the user-declared/not-discovered legend. See `README.md` for the export command and exact CSV headers.
- Diagram layout is radial: configured inventory routers form the central core; connected firewalls, switches, servers, VLAN containers, and the optional Internet cloud grow outward along graph-distance branches. `topology.py` owns placement/routing. Do not generate illustrative routers, switches, or host cables. Device `vlans` and `internet` declare router connections; connected empty VLANs are allowed. VLAN ranges are declared in configuration JSON; there are no built-in VLAN rules. Repeatable `--vlan-range` and `--vlan-map` options extend configuration rules. Unmatched private hosts use Unknown VLAN. Multi-subnet non-inline hosts live under their first eligible private interface's VLAN, with all IPs retained; do not assume `/24` when a prefix is absent. Display VLAN labels on containers, not individual hosts.
- Links use unique ports and obstacle-aware orthogonal paths without shared segments; unavoidable crossings in dense graphs use bridge arcs. Preserve explicit waypoints (disable automatic edge routing). Each movable host container has a bold hostname directly above its IP addresses, followed by the endpoint icon and OS details. Keep routing clear of cards and labels.
- `--config configuration.json` loads explicit VLAN ranges and hostname-keyed device settings without editing the CSV. CLI rules extend/override the supplied `vlans` list. Router type and KCT status are independent; configured roles and KCT markings belong to the existing host container.
- `firewall` is a device type with a dedicated icon; firewalls follow their configured radial branches and support explicit `vlans`/`internet` links. Servers support a non-empty custom `server_type` label (Exchange, Web, File, or other roles) requiring `type: server`. Preserve labels and KCT markings independently of type.
- Device `notes` is an optional string, rendered as a wrapped right-hand panel inside the movable host container. Reserve its width/height in layout and routing; preserve multiline text and keep device labels/icons in the original left-hand card. Empty notes have no panel.
- Top-level `connections` entries use `from`/`to` inventory hostnames (case-insensitive), with reserved source `internet` for the cloud. Explicit directed paths must be acyclic; all participating devices appear once, and arrows preserve direction independently of radial placement. Keep existing direct VLAN/Internet links supported, deduplicate identical rendered links, and validate unknown endpoints before writing output.
- Run tests with `.\.venv\Scripts\python.exe -m unittest discover -s tests -v`; default discovery from the root does not find this test directory.
